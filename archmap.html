01 — Raw Data Source
NYC TLC Yellow Taxi · Parquet
NYC Taxi & Limousine Commission (TLC) Yellow Taxi trip records. Single-month Parquet dataset ingested as the raw source. 3,066,766 trip records covering pickup/dropoff times, locations, fares, distances, and passenger counts.
parquet 3,066,766 records NYC TLC

Bronze Layer
🔨
02 — PySpark Cleaning Engine
pyspark_cleaning.py
Distributed cleaning using PySpark: drops nulls and duplicates, filters invalid fare/distance/passenger values, casts column types, and extracts temporal features (hour, day_of_week, month). Outputs cleaned Parquet to S3 Bronze bucket.
PySpark null filtering type casting feature extraction
cleaned Parquet → s3://bucket/bronze/
🪣
03 — AWS S3 · Bronze Bucket
s3://nyc-taxi-bucket/bronze/
Raw cleaned data persisted in Parquet format on AWS S3. Serves as the durable source of truth for all downstream transformations. Registered as an external table in AWS Glue for Athena querying.
AWS S3 Parquet AWS Glue
Athena external table scan
Silver Layer
🔍
04 — AWS Athena · SQL Queries
athena_queries.py · AWS Athena
Serverless SQL engine queries the S3 Bronze Parquet files via AWS Glue catalog. Executes aggregation queries for zone-level demand metrics, temporal patterns, and fare distributions. Results feed into dbt staging models.
AWS Athena serverless SQL AWS Glue catalog
ref() → staging models
🔧
05 — dbt Staging Models
models/staging/stg_trips_cleaned.sql
dbt staging models standardise schema, rename columns, apply business logic filters, and cast types for Silver layer consistency. Includes dbt tests for not_null, unique, and accepted_values constraints. Materialised as Athena views.
dbt staging models dbt tests Athena views
ref(stg_trips_cleaned) → mart models
Gold Layer
⭐
06 — dbt Mart Models
models/marts/fct_trips.sql · dim_zones.sql
Gold-layer fact and dimension tables following Kimball dimensional modelling. fct_trips aggregates trip-level metrics; dim_zones holds zone lookup data. Materialised as Athena tables on S3 Gold bucket. Serves as the feature store for XGBoost training.
dbt marts Kimball fct_trips dim_zones
temporal holdout split → train/test
ML · Inference
🤖
07 — XGBoost Demand Forecasting
train_model.py · model.pkl
XGBoost regressor trained on Gold-layer features (hour, day_of_week, PULocationID, month) to forecast trip demand per zone per hour. Uses chronological train/test split (temporal holdout) to prevent data leakage. Excludes fare/distance/duration — derived post-prediction features.
XGBoost temporal holdout R²=0.91 RMSE=21.63 +70.1% vs baseline
model.pkl → inference → predictions
Presentation
📊
08 — Streamlit Dashboard
app.py
Interactive analytics dashboard visualising Gold-layer metrics and XGBoost demand forecasts. Charts include zone-level demand heatmaps, hourly trip distributions, fare analysis, and forecast vs actuals comparison plots.
